# Спутник Guard — защита целостности сборки

© 2026 Alexandr. Основной код форка: OpenCode, MIT, © 2025 opencode.

Проверяет, что запущенная программа — именно та, которую выпустили.
Если нет, не запускает и показывает окно с адресом настоящей.

---

## Что это даёт и что не даёт

**Даёт.** Подделку нельзя выпустить под нашим именем. Чтобы подписать
свою сборку нашей подписью, нужен приватный ключ, а он не уезжает с
машины сборки. Подпись ломается от первого изменённого байта.

**Не даёт.** Абсолютной защиты нет. Любой `.exe` можно распаковать и
перепаковать. Если человек вырежет проверку вручную — она исчезнет. Но
вместе с ней исчезнет и подпись, и Windows начнёт ругаться. То есть
подделку нельзя продать как нашу, но вырезать проверку можно.

**Честная формулировка цели:** не «невозможно сломать», а «подделку
нельзя выдать за оригинал».

---

## Как это работает

```
СБОРКА
  собрать манифест  →  подписать приватным ключом  →  положить рядом
                                                       sputnik.manifest.json
                                                       sputnik.manifest.sig

ЗАПУСК
  прочитать манифест
      нет файла            → НЕ ЗАПУСКАЕМ
  проверить подпись вшитым публичным ключом
      не сходится         → НЕ ЗАПУСКАЕМ
  посчитать SHA-256 каждого файла
      хоть один не совпал → НЕ ЗАПУСКАЕМ
  всё сошлось
      запускаем
```

Проверка идёт **до** главного окна, **до** сети и **до** распаковки
тяжёлых ресурсов. Пока она идёт, программа только читает файлы.

## Ключи

| | Где | Попадает в поставку |
|---|---|---|
| Приватный | `keys/signing_key_ed25519.bin` | **никогда** |
| Публичный | вшит в `sputnik_guard/keys.py` | да, он и так есть в коде |

Публичный ключ вшит в код, а не лежит файлом рядом. Иначе подделка
выглядела бы так: меняем ключ, меняем манифест, подписываем своим.
Вшитый ключ такому не поддаётся.

**Приватный ключ в `.gitignore`.** Потерян — придётся выпускать новую
версию с новым ключом, старые перестанут проходить проверку.

## Команды

```bash
# создать ключи (один раз)
python tools/init_keys.py

# собрать и подписать манифест
python tools/build_manifest.py <папка-с-программой>

# проверить, что защита работает
python tools/selftest.py
```

`selftest.py` гоняет семь сценариев на временных файлах и ничего не
трогает в настоящей сборке:

| Сценарий | Ожидание |
|---|---|
| честная сборка | принимается |
| изменённый файл | отклоняется |
| пропавший файл | отклоняется |
| подпись чужим ключом | отклоняется |
| правка манифеста | ломает подпись |
| путь за пределы папки | отбрасывается |
| подмена манифеста и подписи парой | отклоняется |

## Подключение к программе

```python
import sys, base64
from pathlib import Path

from sputnik_guard import enforce, public_key_from_bytes
from sputnik_guard.keys import PUBLIC_KEY_B64

def main() -> int:
    root = Path(sys._MEIPASS if getattr(sys, "frozen", False) else __file__).parent

    # Не запускаемся, если сборка изменена. Дальше — как обычно.
    enforce(root, public_key_from_bytes(base64.b64decode(PUBLIC_KEY_B64)))

    ...  # остальная программа
```

`enforce()` возвращается только когда всё в порядке. При проблеме
показывает окно и завершает программу.

## Окно при отказе

```
            Это не оригинальный файл

   Проверка не пройдена — программа не запустится.

   Три возможные причины:

     •  Файл изменён после сборки. Скачайте заново
     •  Антивирус поправил файл при распаковке
     •  Установка не завершилась

   ─────────────────────────────────────────────
   Оригинал:  info.test

   [  Закрыть  ]        [  Открыть сайт  ]
```

**Почему причин три, а не одна.** Самая частая жалоба на такие программы
— «антивирус ругается», и это ложное срабатывание. Пользователь лечит
файл, антивирус его перепаковывает, проверка падает. Если написать
только «файл изменён», человек решит, что его взломали. Все три причины
реальны, поэтому все три названы.

**Домен написан текстом**, а не только в кнопке: если открытие не
сработает, человек всё равно видит, куда идти. И это работает без сети.

## Домен

Сейчас в `sputnik_guard/guard.py`:

```python
INFO_URL = "info.test"
```

Домен `.test` зарезервирован по RFC 6761 и в интернете не разрешается
никогда. Это сделано намеренно и для заглушки полезно: если значение
нечаянно уедет в продакшен, это сразу видно по битой ссылке, а не через
час мучений «почему домен не открывается».

**Перед выпуском заменить одной строкой на боевой домен.**

## Ограничения

- **PyInstaller-сборки распаковываются.** `.pyc` достаётся тривиально.
  Защита ловит подмену, но не прячет исходники. Если нужно именно
  скрыть — Nuitka или Tauri, это отдельный разговор.
- **Смартскрин** — отдельный механизм от подписи. Свежая сборка с
  идеальным сертификатом всё равно получит щит, пока не наберёт
  репутацию скачиваниями. Деньгами не обходится.
- **Пользовательский сертификат** снимает щит, но ругается. Подпись
  перестаёт работать, если проверка обходится руками, — но тогда
  пропадает и подпись.

## Переход на платный сертификат

Код не меняется. Подпись сборки и подпись Authenticode — разные вещи:
наша подписывает манифест, коммерческая подписывает `.exe`. Они
живут параллельно и не мешают друг другу.

1. Получить сертификат (SignPath бесплатно для открытого кода)
2. Подписать `.exe` и установщик в конвейере сборки
3. Выпустить новую версию

До тех пор программа работает с самоподписью: винда предупредит о
неизвестном издателе, но проверка целостности уже работает.
